# 深层参考：LaTeX 编译后 PDF 版面与浮动体审查

LaTeX 源码编译成功不代表论文版面合格。任何用于提交、交付或正式审核的 LaTeX 论文，都必须完成“源码编译 + 日志检查 + PDF 逐页渲染 + 视觉复核”。仅检查 `.tex` 或仅看到编译返回码 0，不足以通过版式审核。

## 1. 按任务范围选择审查链

### `micro-revision`

```text
编辑现有 master_source
→ 编译生成 PDF
→ 检查日志和引用状态
→ 渲染并检查受影响页
→ 若分页/浮动/编号向外传播，升级为 revision
```

### 全文排版、候选终稿、提交审核

```text
编辑现有 master_source
→ 编译生成 PDF
→ 检查 LaTeX 日志和引用状态
→ 将 PDF 全部页面渲染为图片
→ 逐页检查图表浮动、分页、空白、裁切和图文邻接
→ 修复源文件
→ 重新编译和渲染
→ 复核当前 PDF 全部必要页面
```

若 PDF 有任何影响阅读或引用关系的改动，必须重新执行后半段，不得沿用旧版截图或旧审核结论。

## 2. 图表浮动检查

每个正式 `figure`、`table` 至少检查以下事项：

- 第一次正文引用应出现在图表之前或与图表处于合理阅读顺序，避免图表提前数页出现；
- 图表原则上位于首次引用的同页、下一页或相邻合理位置，不能漂移到与讨论脱节的章节；
- 图题、表题必须与对应对象紧邻，不得孤立到另一页；
- 不得出现一个小图/小表独占整页而上下留下大块无意义空白；
- 不得因为浮动体把章节标题、短段落挤成孤行；
- 多张连续图表不能把数页正文完全推迟，导致“先看结果后看解释”；
- 跨页表格应使用适合跨页的结构，如 `longtable`，而不是让普通 `table` 强行漂移；
- 图表尺寸不得越界、裁切、压住页码或正文；
- 同一组图若必须共同解释，应优先合理组合，而不是让子图散落在不同页。
- 多子图默认最多两列；三维图、机构示意、密集标注或坐标信息复杂的图不得为了压缩页数排成四列，必要时拆成两幅图；
- 最终 PDF 中的坐标轴、图例、单位、刻度和图内文字必须在实际版面尺寸下可读；独立原图清晰但缩入 PDF 后不可读，仍视为版面不合格。

## 3. LaTeX 浮动策略

默认优先使用正常浮动行为，例如 `[htbp]`。不要为了固定位置给所有图表统一使用 `[H]`。

`[H]` 只在正常浮动已经破坏阅读顺序且局部固定确有必要时使用。大量 `[H]` 容易造成大块空白、分页僵硬和标题孤立。

当图表跨越章节边界或漂移过远时，可按实际情况采用：

- `\FloatBarrier` 限制特定逻辑边界；
- 调整图表大小或拆分；
- 调整正文引用位置；
- 将过大的普通表改为 `longtable`；
- 在必要的大章节边界使用 `\clearpage`，但不得用它机械消除所有浮动。

先修复产生漂移的结构，再考虑强制定位。

## 4. 日志检查

正式审核至少检查：

- `LaTeX Error`；
- `Overfull \\hbox` / `Overfull \\vbox`；
- `Float too large for page`；
- `Too many unprocessed floats`；
- `Float(s) lost`；
- 未定义引用或文献；
- 要求重新编译以更新交叉引用的警告。

可运行：

```bash
python scripts/audit_latex_build.py main.tex --log main.log --strict
```

该脚本只能发现源码和日志层面的风险，不能代替逐页视觉检查。

## 5. PDF 渲染检查

优先使用可靠渲染器将全部页面渲染为 PNG，例如：

```bash
python /home/oai/skills/pdfs/scripts/render_pdf.py paper.pdf --out_dir renders/paper --dpi 160
```

如果该脚本不可用，可使用当前环境中可靠的 PDF 渲染方式。关键要求是**检查最终 PDF 页面本身**，而不是只查看 LaTeX 源码。

视觉检查至少覆盖：

- 图表是否漂移；
- 图表是否出现在正确章节；
- 题注与图表是否绑定；
- 是否存在半页以上异常空白；
- 是否有文字、表格、公式或图像越界/裁切/重叠；
- 页眉、页脚、页码是否正常；
- 标题附近是否出现不自然分页；
- 图表引用与实际页序是否顺畅；
- 多子图是否默认不超过两列，复杂图是否已经拆分而不是缩小到不可读；
- 表格单位是否位于物理量列或表头，数值列是否避免重复单位；
- 最后一页和附录是否存在意外空页。

## 6. 通过条件

`format_and_citation` 在 LaTeX 最终稿场景下不得仅凭“编译成功”判为 `PASS`。至少需要两类证据：

1. 日志层证据，例如 `latex-build-audit.txt`；
2. 最终 PDF 渲染后的人工版面复核记录，例如 `renders/final/page-01...` 与审核页码范围。

没有逐页检查最终 PDF 时，只能标记 `UNVERIFIED` 或 `NEEDS_VALIDATION`。


## 7. 当前 PDF 视觉证据

视觉审核必须绑定到当前 PDF，避免修改后继续沿用旧截图或旧结论。推荐从 `templates/latex-review.json` 生成审核记录，并运行：

```bash
python scripts/validate_latex_review.py latex-review.json --strict
```

记录至少包含：

- 当前 PDF 路径；
- 当前 PDF SHA-256；
- 实际页数；
- `scope = affected | full`；
- 已渲染页码；
- 已人工/视觉复核页码；
- `affected` 模式下的受影响页码；
- 审核状态。

`full` 审核只有在所有页面均被渲染和复核、且记录中的 SHA-256 与当前 PDF 完全一致时才可通过。`affected` 只适用于 micro-revision / 局部 revision，并要求所有受影响页均覆盖。任何重新编译导致 PDF 哈希改变，旧 review 自动失效。
