# 深层参考：数学建模论文正文语言契约

本文件只约束论文语言，不改变模型、数据、公式和专业术语。目标是减少模板化 AI 痕迹，使正文接近真实竞赛论文的直接、克制、可核验表达。

## 1. 最高原则

语言优化的优先级低于专业准确性。不得为了“去 AI 味”改写已经准确的领域术语、模型名称、指标名称、变量定义、数据集名称、软件名称和公式符号。

例如 MILP、蒙特卡洛模拟、异方差、多重共线性、Pareto 前沿、RMSE、F1-score 等术语应按领域惯例保留。若“耦合”等词确实描述数学或物理关系，也应保留；只删除没有具体含义的修辞性组合。

## 2. 正文基本写法

优先使用明确的主语、动作、对象和依据。一个句子尽量只承担一个主要逻辑关系，避免连续堆叠抽象名词和评价词。

段落围绕一个局部任务展开。通常先说明本段要处理的问题，再给模型、计算或证据，最后解释结果。不要机械复制同一种三句模板，也不要每段都加总结性套话。

评价性表述必须能回答“依据是什么”。能用数值、公式、约束、图表或检验结果说明时，不使用“较好、较强、先进、有效”等空泛形容词替代证据。

## 3. 标点使用约束

### 中文引号

正文中不要用 `“ ”` 给普通词语加强调、制造概念感或作比喻。以下情况才使用：

- 原题、规范或文献的必要直接引语；
- 需要准确保留的原始标签或特定称谓；
- 讨论某个词本身。

能直接写清楚的内容不用引号。例如不要写“更优”的方案、“关键”的变量、“智能化”的求解过程。

### 圆括号

不要把补充解释、转折、评价或例子长期塞进 `（ ）`。若内容影响理解，应改成完整句子；若不影响理解，应删除。

允许的常规用途包括：

- 专业缩写首次定义，如平均绝对误差（MAE）；
- 公式、参数、单位或编号的规范写法；
- 必要的同义名称或标准名称；
- 模板或参考文献格式要求的内容。

不得因为减少括号而删除必要的缩写定义、单位、公式编号或专业信息。

### 冒号

连续正文中尽量不用 `：` 代替完整句子。尤其避免反复出现“结果表明：”“分析如下：”“具体而言：”“原因如下：”后接解释。

冒号主要保留给正式定义、明确列举、算法输入输出、符号说明和确有必要的列表。普通结果解释改为自然陈述句。

### 其他标点

- 少用破折号承担修辞强调或插入说明；
- 少用分号串联过多独立判断，逻辑较多时拆句；
- 不用感叹号表达评价；
- 不用省略号制造语气；
- 标点调整不得破坏公式、引用、编号和程序代码。

## 4. 高频 AI 套话

以下词语和句式原则上不用，除非它们属于不可替换的正式名称或具有严格技术含义：

- 毋庸置疑、显而易见、不言而喻、不难发现；
- 值得注意的是、需要指出的是、必须强调的是；
- 综上所述、由此可见、从某种意义上说、在这一背景下；
- 深刻揭示、深刻体现、切中要害、不可磨灭的贡献；
- 范式转移、颠覆性、革命性、里程碑式、卓越、强大；
- 全面赋能、有效赋能、协同增效、耦合内聚、形成闭环；
- 从本质上讲、本质上实现、本质性提升；
- 为后续研究奠定坚实基础、提供强有力支撑、具有重要理论意义和现实意义；
- 不仅……而且……、既……又……等成对修辞在相邻段落中反复出现；
- 首先、其次、再次、最后在连续段落中机械排列。

这些规则针对空泛修辞，不针对专业术语。例如统计检验得到显著性结论时，“显著”可以使用；数学模型确有耦合关系时，“耦合”可以使用。不得按词表机械替换。

## 5. 空泛评价改写规则

出现以下类型的判断时，优先给具体证据：

- “预测精度较高”改为给出测试集指标及基线差异；
- “模型较稳健”改为给出参数扰动、重复实验或情景变化下的结果范围；
- “方案更优”改为说明目标函数、成本、时间或约束改善多少；
- “结果合理”改为说明与理论边界、历史数据、常识或基准方案的一致关系；
- “模型有效”改为说明它完成了哪一项任务，并通过了哪一种检验。

没有证据时删除评价，不补造数字。

## 6. 连接和解释方式

优先依靠事实顺序和因果关系连接句子，不依赖大量路标词。

可以直接写：

- 根据表 4，方案 A 的运输成本低于方案 B；
- 当参数增大时，目标函数先下降后趋于稳定；
- 约束式（12）保证每个需求点只分配一次；
- 该误差主要来自高峰时段样本，因此后续单独检查这一时段。

少写：

- 值得注意的是，模型取得了较为理想的效果；
- 由此可见，该模型具有较强的鲁棒性；
- 这一结果深刻揭示了变量之间的本质联系。

## 7. 专业术语保护

修改语言前先判断目标词是否属于：

- 数学、统计、运筹、机器学习、图论、仿真等领域的标准术语；
- 赛题给定名词；
- 数据字段或变量名称；
- 模型、算法、指标、数据集、软件或标准的正式名称。

属于上述情况时优先保留原词。只有修辞性包装可删改。若术语可能影响含义，不做同义替换。

## 8. 段落自检

完成正文后逐段检查：

1. 本段是否有明确任务或结论；
2. 关键判断是否有公式、数值、图表或逻辑依据；
3. 是否存在无必要的引号、括号、冒号、破折号或分号；
4. 是否使用了高频 AI 套话；
5. 是否用形容词代替了可量化证据；
6. 是否为了去 AI 味误改了专业术语；
7. 与相邻段落的句式和开头是否过度重复。

语言问题默认按 P2 处理；若改写造成术语失真、结论夸大或事实含义改变，则升级为 P1 或 P0。

## 9. 风格脚本的使用边界

可运行：

```bash
python scripts/lint_paper_style.py paper.tex --strict
python scripts/lint_paper_style.py paper.docx --strict
```

`--strict` 只把高度可疑的修辞词列为错误。引号、括号、冒号、空泛评价和部分过渡词主要作为人工复核警告。警告不要求机械删除；如果属于缩写、公式、正式标签、统计术语或其他规范场景，应保留并在审核记录中说明。

`prose_clarity` 标记 `PASS` 时，至少应能说明高风险错误已经清除，剩余警告均经过人工复核。脚本不能判断文字是否由 AI 生成，也不能替代专业写作判断。

## 10. 问题驱动与元话语密度

不能依据论文文本断定作者是否使用 AI；审核应关注可观察的写作风险。以下表达不是一律禁止，但连续高密度出现时需要人工复核：

- “统一为……框架”“便于逐层检查”“完整覆盖”“预先声明的选择规则”等对自身方法结构的评价；
- “该结果仅反映……”“不构成……证明”等边界声明在每节重复出现，却没有新增证据或具体适用条件；
- 每个段落都机械按照“做了什么 → 为什么 → 检验什么 → 证明什么”展开，导致问题、数据和结果被模板结构遮蔽；
- 用“严谨、稳健、先进、有效、合理”等词代替数值、公式、图表或检验结果。

优先改成题目驱动的叙述：

```text
题目约束或数据特征 → 模型选择 → 实际计算结果 → 与本题对应的解释
```

只保留真正必要的限定语。没有证据时删除评价，不为了表现“严谨”补写自我审查式结论；专业术语、模型名称、指标和公式符号仍须保持准确。高密度模板化语言登记 `AI_STYLE_OVERUSE`，但不得把该代码解释为已经证明使用了 AI。

## 11. 去防御性写作：先分类，再删除或重构

防御性表达不是简单的禁词问题。任何限定、免责、犹豫或否定句，先判断它在论证中承担什么功能，再决定保留、移动、收缩或删除。至少区分六类：

1. **无必要免责**：只为预防假想批评，没有增加证据、范围、逻辑或读者指引；删除。
2. **必要适用范围**：影响结论适用对象、参数区间、数据范围或场景；保留，但优先改成正面范围表述。
3. **真实方法局限**：会影响模型有效性、误差解释、外推或决策使用；保留，并放在方法、结果讨论或局限性等合适位置。
4. **有用概念对比**：`不是 X 而是 Y` 本身承担定义或区分作用；可以保留，但不得成为习惯性句式。
5. **证据强度限定**：由样本量、实验设计、统计检验或模型假设决定；应具体说明不确定性的来源，而不是叠加模糊副词。
6. **冗余澄清**：重复解释正文已经清楚表达的内容；删除或合并。

禁止把“谨慎”理解为每段增加一句“本文不声称……”“该结果不代表……”“不构成……证明”。如果这些句子主要用于保护作者免受假想反驳，而不改变读者对结果的正确理解，应删除。

### 11.1 正面界定范围（Positive Scope）

优先写“研究什么、适用于什么、在哪个区间有效”，少写“没研究什么、不能覆盖什么”。

不推荐：

> 由于实际情况复杂，本文无法考虑所有影响因素，也不声称模型适用于所有场景。

推荐：

> 根据题目目标和数据可得性，模型选取需求强度、运输距离和容量约束描述当前决策场景。

不推荐：

> 本文不能证明该参数在任意取值下都有效。

推荐：

> 敏感性分析覆盖参数在基准值上下 20% 的变化范围，结论在该区间内保持稳定。

范围需要收缩时，直接收缩主张，不用多层免责声明修补过宽结论。

### 11.2 限定语放置规则（Limitation Placement）

必要边界只在真正影响当前句子解释时就地说明；否则集中放入模型假设、方法说明、结果讨论或局限性，不要散落在摘要、引言、贡献句、段首和结论中。

高影响位置默认先呈现问题、方法、发现或结论。除非限定条件决定该句是否成立，不以“尽管……”“虽然……”“需要说明的是……”开篇。

摘要和结论尤其避免重复自我审查。必要局限已经在正文说明时，结论只保留影响实际使用的关键边界。

### 11.3 以证据定标，不以犹豫词降压

真实不确定性必须说明来源。避免在同一句中叠加“可能、或许、似乎、一定程度上、潜在、初步”等多个模糊词。

不推荐：

> 结果可能在一定程度上潜在表明该变量或许会影响目标值。

推荐：

> 在当前样本中，该变量与目标值呈正相关；由于未控制季节因素，该结果不作因果解释。

这里的限定来自具体设计缺口，因此应保留。若没有明确的不确定性来源，则删去习惯性犹豫词，直接陈述证据能够支持的结论。

## 12. Claim-forward：段落先推进论证，不先替审稿人攻击自己

段落的首要任务是推进论文，而不是预先回答所有可能反驳。默认顺序为：

```text
当前问题 / 核心判断
→ 证据或模型关系
→ 解释其为什么成立
→ 必要时补充真正影响解释的边界
```

优先让段首出现本段的任务、结论、模型关系或关键发现。不要把段落写成“局限 → 道歉 → 解释 → 最后才说结论”。

“一个段落一个主要任务”不是固定三句模板。允许段落长短和组织方式随内容变化，但不应在同一段混入主张、道歉、例外、重复澄清和总结性套话。

## 13. 最终逻辑叙事：论文不是建模工作日志

正文写最终成立的推理链，而不是记录研究过程。除非方法选择过程本身具有论证价值，不按“先尝试 A、再改 B、后来发现 C、最后采用 D”的时间顺序写作。

优先组织为：

```text
题目为什么需要处理这个关系
→ 数据或约束呈现什么特征
→ 因此采用什么模型或处理
→ 模型如何刻画该特征
→ 结果怎样回答本问
```

实验和对比是论证工具，不是结果仓库。每个关键实验至少应承担一种职责：支持核心方法有效、说明优势来自什么机制、验证目标场景价值、排除合理替代解释或界定模型边界。

不得为了“扬长避短”隐藏会改变核心结论的负面结果；**不得隐藏**影响读者判断的重要证据。对不占优但必须报告的结果，应客观解释其对应的目标、约束和权衡，不把局部不足扩大为对整个模型的自我否定，也不把弱结果包装成不存在的优势。

## 14. 中文句法去机械感

去 AI 味不能只靠词表。还应检查句法结构：

- **定语链过长**：避免连续多层“的”字修饰导致主干迟迟不出现；优先把条件、动作和对象拆成完整句或短分句。
- **主谓宾主干隐藏**：句子较长时优先明确“谁/什么—做什么—得到什么”，再补条件与原因。
- **抽象名词连续堆叠**：如“基于……机制的……框架的……能力提升”应改为具体动作和关系；但“机制、稳健性、耦合、拓扑、动态”等具有明确数学或专业含义时必须保留。
- **句长失控**：中文长句若同时承担多个逻辑关系，应拆分；不设机械统一字数上限，但超过约 50 个汉字且存在多重转折、定语或并列时必须人工复核。
- **同构句式重复**：相邻段落不要都以“针对……本文……”或“结果表明……”起句，也不要都用相同的四步解释模板。

句法优化不得损坏公式、变量、数据、LaTeX 宏、引用、标签和交叉引用。

## 15. 改写时的三层保护

论文润色按以下优先级处理：

```text
事实层：数据 / 公式 / 模型 / 图表 / 引用 / 已完成实验
    → 默认保护，不因语言优化改变

语义层：主张 / 因果 / 适用范围 / 证据强度
    → 只有证据支持时才能重构或收缩

表达层：句式 / 套话 / 防御性 / 冗余 / AI 机械感
    → 重点优化
```

如果去防御性或去 AI 改写会扩大主张、掩盖真实局限、删除影响结论的负面证据或改变专业含义，必须停止该改写并保留原有科学边界。

## 16. 专项改写流程

对已有段落进行学术化重构时按以下顺序：

1. 标出本段真正要表达的主张或任务；
2. 绑定能支撑它的公式、数值、图表、检验或逻辑依据；
3. 对限定句执行“无必要免责 / 必要范围 / 真实局限 / 概念对比 / 证据限定 / 冗余澄清”分类；
4. 删除无信息增量的免责和重复澄清；
5. 将消极范围改为正面范围，将模糊犹豫改为具体不确定性来源；
6. 重排段落，使核心判断先行、证据紧随、边界后置且只出现一次；
7. 清理定语链、长难句、模板过渡和抽象名词堆叠；
8. 最后核对事实层完全未变，且没有隐藏影响核心结论的限制或结果。

终稿人工复核时，除原有段落自检外，再问：

- 这句话是否主要为了防御一个尚未出现的假想反驳？
- 能否把“不能/不代表/不声称”改成更准确的正面适用范围？
- 限定语是否被重复写在摘要、引言、结果和结论多个位置？
- 段落是否先说限制，几句之后才出现真正结论？
- 是否用多个犹豫词代替了对不确定性来源的说明？
- 是否把研究过程写成了工作日志，而不是最终成立的论证链？
- 是否因为“扬长避短”而漏掉会改变核心结论的重要负面证据？
- 句子是否因多重“的”字定语、抽象名词或连接词堆积而难以找到主干？
