# 入口：handoff（断点续接）

适用于用户已经完成部分工作，agent 从任意中间阶段介入。目标是继承可用成果，只检查进入下一步所必需的接口，不把任务重做一遍。

## 1. 先识别已有成果

按实际可见材料判断当前最高可用检查点：

- `after_problem_reading`：已有题意拆解、子问题或任务链；
- `after_data_preprocessing`：已有清洗数据、字段说明或探索性分析；
- `after_model_construction`：已有建模思路、公式、变量、约束或算法方案；
- `after_computation`：已有代码、配置、日志或数值结果；
- `after_results`：已有稳定结果表、图表或检验结果；
- `after_draft`：已有论文正文或接近完整稿件；
- `mixed`：材料来自多个阶段但缺少连续链，例如只有代码没有模型说明，或只有图表没有结果文件。

不要仅根据用户说“已经做完”就判定为已验证，要根据实际可见材料确定状态。
若缺少某个上游原件，但当前局部任务不依赖它，可以继续并将相关判断保留为 `UNVERIFIED`；只有缺失信息会实质影响当前计算、结论或一致性时才阻断。不要为了形式完整要求用户补交无关材料。

## 2. 给已有阶段标状态

阶段状态只能使用：

- `NOT_STARTED`：没有可用成果；
- `INHERITED_UNVERIFIED`：已有成果，但尚未完成进入下一阶段所需的最小核验；
- `INHERITED_VERIFIED`：已有成果，并已通过当前任务所需的接口核验；
- `COMPLETED`：本次执行中完成并核验；
- `NEEDS_REVIEW`：存在局部缺口或冲突，不能直接依赖；
- `BLOCKED`：存在足以阻止下游工作的硬问题；
- `NOT_APPLICABLE`：当前任务不需要该阶段。

“继承并核验”不等于重新推导全部内容。只检查下游真正依赖的接口。

工作流只追踪当前有效方案链。已经明确废弃、被替代且不再支撑任何正文结论的旧分支，应标记 `NOT_APPLICABLE` 或移出活动工作流，并在 notes 中说明原因；不要让无关旧实验阻塞当前终稿。

## 3. 最小桥接检查

### 已有题意拆解后介入

只检查：

- 子问题是否覆盖原题主要任务；
- 每问输入、输出和硬约束是否明确；
- 是否存在明显改变原题目标的假设。

通过后直接进入数据或模型阶段，不重新写一遍题意分析。

### 已有建模思路后介入

只检查：

- 模型是否能产生题目要求的输出；
- 关键变量、参数、目标、约束和单位是否可落到代码；
- 数据是否能够支撑模型；
- 检验对象是否可定义。

通过后直接进入编码或实验，不重新罗列无关备选模型。

### 已有代码后介入

先从代码反向建立最小模型映射：

- 输入文件与字段；
- 主要参数和默认值；
- 目标函数、核心公式或算法步骤；
- 输出文件、指标和图表；
- 随机种子、数据划分和关键配置。

若题目或模型说明可见，再核对代码是否实现它们。若数据和环境可用，应实际运行或至少执行最小可运行检查；无法运行时标记 `UNVERIFIED`，不得把代码存在当作结果正确。

### 已有结果或图表后介入

先找结果来源。能够追溯到代码、日志或结果文件时再用于正文；只有图片或手抄数字时，只能做图文与逻辑审核，不能反推为已验证实验结果。

### 已有论文后介入

先识别其主编辑源和模板来源。若同时存在 `.tex/.docx/PDF`，优先继续编辑能够生成当前稿件的可编辑源；PDF 默认用于核对。先判断用户需要续写、修改还是审核。保留已经正确的章节，只处理目标范围及依赖项；除非发现 P0/P1 冲突，否则不得为了统一风格整篇重写，也不得无理由把 Word 改成 LaTeX 或把 LaTeX 改成 Word。


## 4. 常见续接路由

| 已有成果 | entry/checkpoint | 通常下一步 | 不应做的事 |
|---|---|---|---|
| 已拆解题意 | `handoff / after_problem_reading` | 数据检查或模型构建 | 重写整份题意分析 |
| 已有完整建模思路 | `handoff / after_model_construction` | 代码与实验 | 再凑一组候选模型 |
| 已有代码和数据 | `handoff / after_computation` 或 `mixed` | 代码核对、运行、结果验证 | 因缺少文字模型说明就从头读题 |
| 已有结果表和图 | `handoff / after_results` | 检验、解释或论文写作 | 从图片反推未提供的实验数据 |
| 已有论文初稿 | `handoff / after_draft` | revision 或 audit | 无理由整篇重写 |

入口检查结束后直接进入用户当前目标，不额外输出一份“流程回顾”，除非该回顾本身有助于说明风险。

## 5. 断链处理

允许从不连续材料继续，但必须补最短缺口，而不是回到第一阶段。

```text
只有代码，没有建模说明
→ 从代码提取模型映射
→ 核对题目接口
→ 继续运行/验证
```

```text
已有模型和论文方法章节，没有代码
→ 保留已核验模型
→ 从 computation-experiment 开始
```

```text
已有结果图，没有原始结果文件
→ 图表可用于版式和叙述审核
→ 数值结论保持 UNVERIFIED
→ 要做结果论证时才要求补结果来源
```

## 6. 禁止行为

- 用户已有成果可用时，机械从 problem-reading 重新开始；
- 因为上游阶段不是本 agent 完成，就默认判为无效；
- 未核验继承材料就把状态写成 `COMPLETED`；
- 发现一个局部问题就推翻全部已有成果；
- 为补齐流程而生成用户没有要求的中间文档；
- 将“已有代码”“已有论文”误认为“结果已经正确”。
