# 模式：micro-revision

目标：以最小修改完成局部论文修订，避免无意义触发完整模型、结果、图表和提交审计。

## 1. 准入条件

仅当以下条件同时成立时使用：

- 修改对象局限于少量正文、单个公式表述、标题、图注、表注或等价的局部排版；
- 不改变模型结构、目标函数、约束、关键参数或数据口径；
- 不需要重新计算正式结果；
- 不重新生成或替换正式图形数据；
- 不修改全局 `documentclass`、核心 `.cls/.sty`、整套编号体系或参考文献集合；
- 用户没有要求全文排版、完整审计、终稿或提交判断。

只要任一条件不满足，使用 `revision` 或更高范围模式。

## 2. 固定执行链

```text
定位唯一 master_source 与目标位置
→ 确认本轮只改指定范围
→ 按项目既有备份机制保护原源
→ 小范围修改
→ 编译实际 master_source
→ 检查本轮新增的 LaTeX error / reference / overflow 风险
→ 检查受影响 PDF 页面
→ 必要时检查前后相邻页
→ 结束
```

不得为了“更干净”另建 `main_fixed.tex`、`paper_new.tex`、`final.tex` 等新主稿。

## 3. 自动升级条件

修改后出现以下任一情况，`micro-revision` 立即失效并升级为 `revision`：

- 分页或页面总数变化且影响后续版面；
- 图表浮动位置明显变化；
- 图号、表号、公式号、章节号或交叉引用传播到目标范围之外；
- 修改触发新的图表重绘、正式结果更新或参考文献变更；
- 需要修改导言区、全局样式或多个章节才能修复；
- 发现与当前修改直接相关的 P0/P1 一致性问题。

micro-revision 可以缩小验证范围，但不能取消编译和对应页面视觉验证。
