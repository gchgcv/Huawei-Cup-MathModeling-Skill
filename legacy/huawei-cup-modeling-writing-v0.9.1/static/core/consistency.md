# 单一事实源与一致性规则

## 1. 统一台账

任务按需要维护以下权威记录：

- **工作流状态**：入口类型、当前检查点、当前阶段、各阶段的继承/核验/阻断状态及证据；
- **问题台账**：子问题、任务、输入、输出、硬约束、评价标准、模型和结果证据；
- **数据台账**：文件、字段、含义、单位、范围、缺失异常、处理方式和数据版本；
- **参数与符号台账**：论文符号、代码变量、含义、数值、单位、来源和信息状态；
- **结果台账**：结果、子问题、数据版本、模型版本、参数版本、脚本、图表和论文位置；
- **关键结论台账 `claims`**：结论文字、证据、适用边界和出现位置；
- **质量报告**：提交状态、门控、P0/P1/P2、诊断评分和修复状态。质量报告不替代前述事实台账。

## 2. 事实源优先级

```text
原题与官方附件
> 用户明确确认
> 原始数据与可复现程序输出
> 统一台账
> 论文正文与图表
> 临时草稿
```

发生冲突时，修改下位内容，不得反向篡改上位事实源迁就正文。继承材料的“已有”状态不改变其事实源优先级，仍需按来源决定可信度。

## 3. 继承材料的记录

从中间阶段介入时，不要求把已有工作重新生成一遍。只需在工作流状态中记录：

```text
entry / checkpoint
stage status
evidence
notes
```

`INHERITED_VERIFIED` 只表示该成果足以支撑当前下游任务，不表示已经独立证明其所有细节正确。若后续任务提出更高验证要求，可以重新打开该阶段。工作流只保留当前有效方案链；已废弃且不再支撑结论的旧分支标记 `NOT_APPLICABLE` 或移出活动链。

## 4. 变更传播链

修改源头后只沿实际受影响关系传播：

```text
问题定义
→ 数据/参数台账
→ 公式与模型
→ 代码配置
→ 原始结果与结果台账
→ 表格和图形
→ 正文
→ 摘要与结论
→ 质量报告
```

不受影响的材料不做形式化重写。

## 5. 最小一致性检查

- 同一符号只有一个含义，同一代码变量对应同一参数；
- 正文、代码、结果和图表使用同一参数值、单位和数据版本；
- 单位换算有来源和记录；
- 图表可由最终结果重新生成，不从图片反向抄数作为事实源；
- 摘要和结论中的关键数字已在正文出现并可追溯；
- 删除或替换模型、表图后同步删除旧引用和旧结论；
- 关键结论台账中的评价性判断有对应结果或检验证据；
- 质量报告状态与未解决问题一致。

## 6. 机器校验边界

可运行：

```bash
python scripts/validate_ledger.py modeling-ledger.json --strict
python scripts/validate_quality_report.py quality-report.json --strict
```

脚本只能检查结构、状态和基础引用关系，不能证明数学推导、程序实现或结论本身正确。
