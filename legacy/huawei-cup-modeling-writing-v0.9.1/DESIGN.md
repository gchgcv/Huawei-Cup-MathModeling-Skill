# 稳健审计版设计说明

## 设计目标

本 skill 优先降低长建模任务中的五类风险：自动补全缺失信息、把建议写成结果、接手已有工作后机械从头重做、局部修改未同步、正文用模板化语言掩盖证据不足。目标不是让 agent 写得更复杂，而是让其更容易遵守边界、继承可靠成果、保持一致并留下可审核证据。

## 核心机制

1. **固定执行契约**：不编造、不偏题、不冲突、结论不越界、简单方案优先。
2. **断点续接入口**：先判定 fresh 或 handoff；已有题意、模型、代码、结果或论文时只做下游所需的最小桥接检查。
3. **最小任务路由**：局部请求不扩展为完整论文。
4. **四态信息**：CONFIRMED、DERIVED、ASSUMED、MISSING。
5. **阶段状态机**：区分继承未核验、继承已核验、本次完成、待复核、阻断和不适用。
6. **证据前置**：下游依赖的是可用证据，不要求本 agent 亲自执行过全部上游阶段。
7. **单一事实源**：问题、数据、参数、结果和关键结论进入统一台账。
8. **证据化判断**：没有具体证据的门控只能 UNVERIFIED，不能 PASS。
9. **先门控后评分**：P0 和硬门控优先于总分，创新只作为低权重诊断项。
10. **提交状态机**：只有完整审核通过时允许 READY_TO_SUBMIT。
11. **正文语言契约**：减少引号、括号、冒号和 AI 套话的修辞性滥用，同时保护专业术语。
12. **文档源契约**：论文编辑先确定唯一主编辑源与模板来源；已有源文件优先继承，fallback 模板永不冒充官方模板。
13. **机器校验**：检查路由断链、台账、handoff 状态、文档模板状态、质量状态、评分封顶、Word 公式和正文风格风险。

## 上下文去重原则

全局常驻规则仍集中在 `execution-contract.md`、`consistency.md`、`quality-gates.md`。阶段流程、输出格式和写作要求按需加载。与“是否允许结束任务”直接相关的少量硬边界（如禁止未经授权新建 LaTeX 主源、局部/终稿验证范围、正式图唯一性）允许在 `SKILL.md` 的完成门中再次出现；这是有意的执行冗余，不复制详细方法。

## 断点续接设计

流程不再假设 agent 必须从读题开始。`handoff` 先识别当前最高可用检查点，再给继承材料标状态。`INHERITED_VERIFIED` 只表示它足以支撑当前下游任务，不表示重新证明了全部上游工作。若材料链不连续，只补最短接口缺口。

例如已有代码但没有文字模型说明时，agent 应从代码提取输入、参数、核心公式或算法步骤和输出，完成最小模型映射后继续运行或审核，而不是强制返回 problem-reading。已有论文时则保留正确章节，只处理用户指定范围和实际受影响依赖项。

工作流只追踪当前有效方案链。已废弃且不再支撑结论的旧模型或旧实验不应因为未核验而阻塞终稿，应标记 NOT_APPLICABLE 或移出活动链。

## 正文风格取舍

“降 AI 感”不能高于术语准确性。风格检查只删除修辞性包装、无证据评价和机械句式，不自动替换模型名、统计术语、指标、变量、数据集和正式名称。风格脚本只报警，不自动改文。

## 内部评分定位

公开评审导向强调假设合理性、建模创造性、结果正确性和表达清晰度，但不同赛题评阅重点不同。内部 100 分仅用于定位薄弱环节，不作为官方固定评分，也不预测奖项。

## 设计取舍

- 不强制完整论文、固定页数、固定章节、复杂模型或创新点；
- 不在常驻上下文堆积算法百科和写作词表；
- 审核默认寻找错误和未验证项，而不是先给积极评价；
- 机器脚本只检查结构和高风险模式，不能替代数学证明、代码运行、专业判断和最终排版检查。


## 文档与模板策略

论文格式不设单一硬编码“默认 Word”或“默认 LaTeX”。默认行为是保留当前可编辑主稿。若当届官方标准文档已发布，它控制最终提交格式；用户已有模板在不冲突时继续使用。只有用户明确要求 LaTeX 且不存在任何可用模板时，才使用 `templates/latex/working-draft/main.tex`。该模板仅保证工作稿结构稳定和 XeLaTeX 可编译，不代表官方格式。

这样做是为了避免 agent 每次自行生成不同 preamble，也避免把上一届模板或自制 LaTeX 错认为当届官方标准。

## v0.8 运行反馈修正

运行测试表明“源文件正确”不等于“最终 PDF 正确”，因此 LaTeX 交付改为 render-first 版面审核。另将信息量不足的文字框/箭头链定义为伪图，防止 agent 用演示文稿式图形填充论文。正文深度改为“论证完整度”而非固定篇幅，避免去 AI 化和追求简洁导致模型推导、参数来源与结果讨论被过度删减。
## v0.8.2 职责边界补充

为避免 Agent/Codex 在多个文件中执行同一规则，本版明确单一职责源：

- `references/result-visualization.md`：只负责正式图文件本身的语言、可读性、视觉检查和图文解释；
- `references/latex-pdf-layout-audit.md`：只负责图表进入最终 PDF 后的浮动、分页、题注邻接和页面版式；
- `references/reference-management.md`：只负责参考文献真实性、相关性、旧题来源边界和引用核验；
- `static/fragments/stage/*`：负责何时调用规则、需要哪些产物，不复制详细规则；
- `static/core/quality-gates.md`：只负责风险严重度、问题代码和是否允许提交，不重新定义执行方法。

对 Codex 类执行环境，凡属于视觉结论必须基于实际渲染产物。绘图脚本运行成功只能证明代码可执行，不能证明图像不存在文字遮挡、刻度重叠或字体异常；无法打开/渲染时应保留 `UNVERIFIED`，而不是推测通过。



## v0.9.0 执行约束增强

本版针对实际 Agent 漏规则问题，不增加无关建模流程，主要把软性说明转为可执行约束：

1. **LaTeX 源权威保护**：没有用户明确的新建授权时，禁止创建新的 `.tex` 主源、修复版、终稿版或提交版；备份不成为新主源。
2. **micro-revision**：局部文字/公式/标题/图注修改采用最小链路；一旦发生分页、浮动、编号、引用、结果或图形传播，自动升级为 revision。
3. **Canonical figure manifest**：正式图目录采用白名单审计；默认 dry-run，清理只移入 `.trash`，仍被项目引用的 unexpected 图拒绝自动移动。
4. **PDF review evidence**：视觉复核绑定当前 PDF SHA-256 和页码覆盖，重新编译导致哈希变化时旧审核失效。
5. **诊断分数降级为末位信息**：先报告硬阻断、证据缺口和可改进项，再显示 Internal Diagnostic Score，避免被误解为官方分数或论文质量总评。

本版暂不引入 handoff 页数/图号/标题自动同步检查。


## 论文写作优先定位（0.9.1-writing）

本版本不把 Skill 继续扩展为端到端建模 Agent。主身份调整为“数学建模论文写作与审校优先”，已有建模、代码、结果和外部能力主要用于提供事实、证据与一致性约束。新增写作规则集中在 `references/paper-prose-style.md`：去防御性句子先分类再处理，优先 positive scope 与 claim-forward 表达；正文写最终成立的逻辑而非研究过程日志；去 AI 味增加定语链、主干隐藏、抽象名词堆叠和长难句等句法风险。任何写作优化均不得改变数据、公式、模型、引用或真实方法边界，也不得隐藏影响核心结论的负面结果。
