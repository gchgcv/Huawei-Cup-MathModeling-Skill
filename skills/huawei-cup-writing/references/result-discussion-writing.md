# Result Discussion Writing

Normative rules: `PROSE-002`, `DEPTH-002`, `DEPTH-003`, `DEPTH-005`, `FIG-004`, `FIG-005`, `CLAIM-001`, `CLAIM-002`, `CLAIM-006`, `ADW-002`.

## Core Result Pattern

1. 先指出最重要的结果或差异；
2. 给出可追溯的数值、区间、排序或图表位置，并在存在自然对照时说明比较对象；
3. 解释结果中的主要现象，说明其与模型结构、约束或题目条件的关系；
4. 说明该结果如何回答当前子问题，并给出题目要求的最终输出、判断或决策含义；
5. 只有在影响解释时加入异常、权衡和适用边界。

## Special Cases

- 模型对比：说明基准、指标和差异幅度；
- 敏感性：只说明实际测试的参数、范围和排序变化；
- 验证结果：说明误差、残差、可行性或理论条件；
- 弱结果：按目标差异和约束解释，不隐藏也不夸大为整体失败。

没有自然对照时，不为了填充结构而虚构 baseline；可以说明绝对水平、题目阈值、约束条件或已完成的验证对象。

caption 与正文不得重复堆叠同一句结论。图内数据、正文数字和受保护结果必须一致。未经任务契约明确授权，不新增差值、比例或百分点；需要派生量时按 `fidelity-and-derived-values.md` 声明来源和计算关系。

## Evaluation and limitation checks

- **评价链**：评价模型或方案时，依次交代采取了什么设计、该设计针对什么问题、证据显示了什么变化，以及这一变化只支持到什么范围。仅因模型名称、公式复杂度或结果看起来平滑而写“先进、合理、有效”，不构成评价证据。
- **局限边界**：发现误差、不可行解、指标不占优或适用范围受限时，先说明观察结果，再指出对应的条件、机制和决策影响。若问题会破坏模型、数据或核心证据的成立基础，应按事实说明问题，不能改写成轻描淡写的“仍有提升空间”。
- **改进对应**：提出后续改进时，明确它针对哪一项已识别局限、改变哪个环节以及预期改善什么结果。没有对应局限或证据的方向只能写成探索性设想，不能写成已经解决该问题的方案。

## Weak and negative results

弱结果不需要被包装成整体成功，也不应被写成整体失败。先报告各指标、对照实验或重复训练的实际差异，再说明它在精度、误差类型、稳定性、计算成本和适用范围之间形成的权衡。例如，某模型可以取得最低 RMSE，同时 MAE、MAPE、重复训练波动或训练时间不占优；此时应把它写成当前实验下的性能—复杂度折中，并保留各项不占优证据。

对于峰值、极端样本或小规模子集，写明样本数和观察到的次数变化。局部大误差次数减少可以作为该子集上的现象，但不能单独升级为稳定改善或普遍机制解释。

## Positive-scope result closure

结果段最后不要用“现有证据不足以支持……”“不能据此证明……”结束。保留必要限制后，优先采用以下结构：

```text
当前结果显示 A，适用于 B；C 层面的表现仍需通过 D 验证。
```

例如：“当前对照实验中该方法取得了更低误差，差异的统计稳定性仍需进一步检验。”这类写法保留了证据强度，而不是把 Review 的禁止性判断直接带入成稿。

“预测值—真实值对比图”用于讨论测试阶段的预测关系；只有材料明确涉及训练阶段时，才用“拟合”解释图中现象。图中现象应与指标和题目决策含义相互对应，不能仅写“基本准确”“效果较好”。

## Result narrative slots

主要结果段应尽量覆盖四种功能：量化结果、比较基准（存在自然对照时）、可解释现象和题意意义。四种功能可以分布在相邻句子或相邻段落中，不要求机械写成固定句数。若只报告一个指标，应继续说明该指标支持哪项识别、分类、评价、优化或决策判断。

## Application closure

每个子问题结束前检查：

- 是否明确给出题目要求的最终输出，而不是停留在指标、权重、路径或聚类结果；
- 是否说明数学结果对应的现实、工程、物理或决策含义；
- 是否把该输出与下一问的输入或后续方案选择联系起来；若两问独立，则明确说明其独立性，不制造递进关系。

## Figure responsibility and reading

引入正式图表时，正文应形成“图表引入—读图提示—结论回扣”的关系：说明为什么需要这张图、读者应先看哪个轴/子图/区域或对照、图表支持哪一项结论。复杂图表若同时包含流程、分布和结果，应明确主要职责和阅读顺序；无法识别主信息时应考虑拆分，而不是继续缩小图内元素。

## Evidence continuity

重述核心结果时，沿“模型或 Project Facts → 计算结果 → 表格/图表 → 结果讨论 → 摘要 → 结论”核对。模型名称、指标定义、单位、排序、关键数字和结论强度必须保持一致；发现冲突时保留冲突并提出核验需求，不自行选择一个口径覆盖其他材料。
