# Anti-Defensive Transformation

Normative rules: `ADW-001`–`ADW-006`, `CLAIM-001`, `CLAIM-006`, `DEPTH-005`.

## Sentence Classification

先把限定句标为以下一种，再决定处理方式：

1. 无信息免责：删除；
2. 必要适用范围：改成正面范围；
3. 真实方法局限：保留并放到影响解释的位置；
4. 有用概念对比：保留其定义作用；
5. 证据强度限定：写明不确定性来源；
6. 冗余澄清：删除或与首次说明合并。

## Transformation Order

```text
识别核心主张
→ 定位支持证据
→ 分类限定句
→ 删除无信息免责
→ 将负面范围改为正面范围
→ 将模糊犹豫改为具体来源
→ 把必要边界放到唯一合适位置
→ 核对主张没有被扩大
```

## Paragraph-final Negative Scope

同一段或相邻段落若反复以“未通过、未包含、未覆盖、未验证、未达到”收尾，
先保留其事实含义，再改成正面证据边界：

```text
跨评委组的稳定增量判定仍未通过
→ 更换评委组后，不同模型给出的增量方向仍不一致。该结果反映的是当前模型和评委组条件下的预测变化

验证协议未包含独立外部测试
→ 当前结果反映模型在内部交叉验证下的表现，外部泛化能力还需在独立样本上进一步检验
```

转换后的句子必须回答“现有证据支持什么、适用于哪里”，不能只把“未”替换成
另一个否定词。若否定本身是核心结果，保留该结果，并在下一句给出其条件和决策含义。
正面改写也不能把现象、原因、条件和范围重新压缩成一句规则化长句。一个句子优先
承担一个主要判断：先写观察结果，再用下一句说明解释范围或判定条件。

不得为了让语气更自信而删除核心负面证据、真实样本边界或方法失效条件。

## Limitation admissibility gate

将局限写得更具体，不等于把所有问题都降级为温和表述。处理前先判断：

- **有界局限**：能够指出影响因素、作用环节、当前证据范围和对结论的具体影响。此类局限应保留，并放在最相关的结果解释或结论位置；
- **核心有效性问题**：涉及变量定义错误、关键约束失真、数据与题意不对应、结果不可复现或主要结论缺少支撑等情形。此类问题不能只改写为“仍有提升空间”，应按证据说明其对模型或结论成立条件的影响；
- **改进方向**：只有与已识别局限存在机制或环节上的对应关系时，才能写成针对性改进。没有对应关系的内容应标明为探索性方向，不得暗示已经修复原问题。

如果无法判断局限属于哪一类，先保留问题事实并列出证据缺口，不以更积极的语气代替判断。

## Positive-scope wording for final prose

`Review` 可以用禁止性句式记录越界风险，`Writing` 则应优先把它转换为正向边界。转换不是把“不能”删掉，也不是把结论写得更强，而是明确当前结果所覆盖的对象、数据、参数区间和验证层级。

```text
“不能认为模型适用于所有城市”
→ “模型迁移至其他城市时，需要依据当地路网、容量和需求重新参数化，并在对应场景下进行验证。”

“不能据此证明注意力机制稳定改善峰值预测”
→ “当前峰值样本中 Attention-LSTM 的大误差次数较少；其在更大样本和重复实验下的表现仍需验证。”

“不能据此宣称方法具有普遍更好的收敛性”
→ “当前对照实验表明，该调整在本题数据和既定设置下缓解了部分搜索停滞；其更一般的收敛表现仍需进一步验证。”
```

论文正文避免使用“现有证据仅支持将其表述为……”来讨论术语等级。直接写实际改动、对照对象和当前证据即可；方法改进、建模特色和模型创新的分级按 `contribution-writing.md` 执行。若显著性检验、外部验证或更广情景尚未完成，应保留该事实，并说明它影响的是哪一层结论。

### Acceptable coverage statements

以下句式通常是在界定研究覆盖范围，不属于无信息防御：

```text
当前模型尚未考虑空间非均匀降雨。
本次实验未覆盖外部数据集。
当前分析采用全区域同比例扰动。
现有验证范围包括当前数据集和既定测试划分。
```

应检查这些句子是否对应真实的方法边界，并避免在摘要、结果和结论中机械重复；不能仅因为出现“尚未”“未覆盖”就删除。需要改写的是把局限写成自我辩解，或用“不能据此……”代替具体覆盖范围的情况。

### Independent interfaces and pending outputs

当问题之间没有直接接口时，独立性应主要通过各自的输入、处理对象、输出和分析用途来呈现，
不要把“不使用、不调用、不依赖、不提供”等否定式说明连续写成接口审计记录。必要时保留一处
容易消除误读的排除说明即可。题目尚未实际求解时，正文应写模型用于确定的对象或待求输出，
不要写“当前尚未完成实际求解”“最终方案仍待计算”等工作状态。

```text
接口审计式：问题三不使用问题一结果，也不调用问题二结果，不为问题二提供参数。
正文式：问题三根据门店面积、商圈客流量、运营成本和历史销量刻画长期经营类型，
其聚类结果与前两问的预测和库存分配分别形成独立结论。

工作状态式：当前尚未完成实际求解，最终启用集合仍待计算。
正文式：该模型用于确定起降点启用情况、需求点分配关系及相应目标函数值。
```
