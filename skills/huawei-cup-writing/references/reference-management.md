# Reference Management

本文件是 Writing 侧的参考文献操作说明；正式质量要求仍以 Shared `REF-001`–`REF-005` 为准。

## When to use

仅在以下任务中加载：

- 写作或完善正式论文；
- 整理、核验或补充参考文献；
- 生成或维护 BibTeX / 文献列表；
- 做终稿引用审计。

纯读题、建模、编程或局部结果分析不应为了形式完整主动扩展成文献检索任务。

## Source and verification order

先确定正文实际需要的依据，再按以下顺序处理：

```text
确定主张或参数需要的依据
→ 查找原始论文、教材、标准或官方资料
→ 核验作者、题名、年份、出版物和 DOI/URL
→ 确认正文实际引用位置
→ 写入文献表或 BibTeX
→ 检查引用键、顺序和格式
```

优先来源包括：

- 方法原始论文、教材或专著；
- 高质量综述；
- 标准、规范、政府或权威机构资料；
- 数据集、软件、算法的官方说明；
- 与题目背景直接相关的可靠学术或行业来源。

每条正式文献都应满足真实、可核验、与正文有明确关系且在正文实际使用。Agent 不得从记忆中拼接看似完整的书目信息。

## Network or source unavailable

如果当前无法联网，且用户未提供足以核验的来源：

- 可以保留待补文献需求；
- 登记 `REFERENCE_UNVERIFIED` 或 `REFERENCE_MISSING`；
- 不得生成虚构作者、题名、期刊、DOI 或 URL 来填满文献表。

## Existing BibTeX and cite keys

编辑已有 `.bib` 时优先继承原格式和 cite key。除非发现重复、错误或用户明确要求，不批量重命名引用键，不为了统一个人偏好重排整个 `.bib`。

修改 cite key 后必须同步核对：

- 正文所有引用命令；
- 文献表条目；
- 交叉引用和构建日志。

## Numeric citation order and format

当目标模板采用顺序编码制时：

- 正文第一次引用必须是 `[1]`，之后按首次出现顺序递增；
- 同一处多篇引用按编号升序排列，例如 `[5,6]`，不写成 `[6,5]`；
- 文献表顺序、正文引用、BibTeX cite key 和交叉引用应相互对应；
- 有官方格式要求时服从官方要求；没有明确要求时，默认采用 GB/T 7714 顺序编码制；
- 书籍、期刊、标准等类型按 `[M]`、`[J]`、`[S]` 等标识统一著录；
- DOI、URL、作者、年份和出版信息应留在对应条目内。

首次引用不是 `[1]`、编号倒置或格式混用时，登记 `REFERENCE_ORDER_ERROR` 或 `REFERENCE_FORMAT_INCONSISTENT`，不能只以“文献内容正确”通过。

## Historical competition materials

历年竞赛官方答案、获奖论文、官方范文、培训机构现成解答和同题完整解题材料不得进入正式学术参考文献，也不能作为自主模型成立的依据。

用户明确要求对照这些材料复盘时，可以把它们标记为对照材料，并与正式参考文献分离。检索旧题相关文献时，应优先搜索模型、算法、领域背景和数据来源本身，而不是搜索现成答案。

## Completion check

写作侧完成前确认：

- 文献表非空，且每条正式条目都有正文关系；
- 作者、题名、年份、出版物、DOI/URL 已核验，或明确标记待核实；
- 没有为凑数加入无关文献；
- 没有把旧题答案或范文混入正式参考文献；
- cite key、正文顺序、文献表顺序和目标格式一致。
